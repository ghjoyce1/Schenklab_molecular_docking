Zinc Metalloprotein Docking Pipeline

Dock many small molecules into many zinc-containing proteins on a SLURM cluster, using AutoDock Vina with the AutoDock4Zn force field.

Overview

The pipeline takes a folder of ligands and a folder of protein structures and docks every ligand into every protein, with the search box centred on each protein’s zinc ion. It uses the AutoDock4Zn approach: a tetrahedral pseudoatom (TZ) is added at the zinc so the scoring function can represent metal coordination.

  1. Ligands are cleaned with scrub.py and converted to PDBQT with Meeko.
  2. Receptors are converted to PDBQT, and zinc_pseudo.py adds the TZ pseudoatoms.
  3. Grids are written (a Python 3 step built into the script) and computed with autogrid4.
  4. Docking runs in Vina with --scoring ad4.
  5. Post-processing runs your postprocess.py to summarise the scores.
No MGLTools is needed. zinc_pseudo.py is plain Python and runs under Python 3, and the grid parameter file is written by a small Python function inside zinc_docking.sh.

Requirements

  • A SLURM cluster, and the account name to charge jobs to.
  • A conda environment called docking containing Meeko (mk_prepare_ligand.py, mk_prepare_receptor.py), scrub.py, vina, autogrid4, and the Python packages your postprocess.py uses. The script creates it from environment.yml if it is missing.
  • A clone of AutoDock-Vina. Only example/autodock_scripts/zinc_pseudo.py is used.
  • AD4Zn.dat, the AutoDock4Zn parameter file, in the job directory.
Create the conda environment once, by hand, before submitting jobs. If several jobs start together and each tries to create it, they can collide.

Quick start

1. Lay out the job directory

MultipleDocking/
├── zinc_docking.sh
├── environment.yml
├── AD4Zn.dat
├── postprocess.py
├── ligands/        # .pdb, .mol2 or .sdf small molecules
└── receptors/      # .pdb or .cif proteins containing a Zn ion

2. Edit the script

Change #SBATCH --account to your account. Then set the path to the AutoDock-Vina scripts, either by editing the line near the top of the file or at submit time:

VINA_SCRIPTS="${VINA_SCRIPTS:-/path/to/AutoDock-Vina/example/autodock_scripts}"

The part after :- is the default. Note the hyphen: ${VAR:-default} is correct, and ${VAR:default} is a syntax error.

3. Submit

sbatch zinc_docking.sh                    # normal run
FORCE=1 sbatch zinc_docking.sh            # redo every step

4. Watch it

squeue -u $USER
tail -f slurm-<jobid>.output
cat slurm-<jobid>.error

What the script does

Ligand preparation

For each file in ligands/ a folder ligands/<name>/ is created. scrub.py adds hydrogens and standardises the molecule, writing <name>_H.sdf, and Meeko writes <name>.pdbqt. Empty scrub output counts as a failure, and files that share a base name (such as x.pdb and x.sdf) are detected and the second one is skipped.

Receptor preparation

Each receptor is converted to <name>.pdbqt, then zinc_pseudo.py writes <name>_tz.pdbqt with TZ pseudoatoms. The box centre is the first zinc atom in the converted file, which works for both PDB and CIF input. Receptors with no zinc are skipped and reported.

Grid and docking, per receptor–ligand pair

  1. Write the .gpf with the box centred on the zinc and the six AutoDock4Zn nbp_r_eps potentials. Atom types are read from the two PDBQT files.
  2. Run autogrid4 to build the affinity maps.
  3. Run vina --scoring ad4 against those maps.

Error handling

A failure in one ligand, receptor or pair is logged and skipped, not fatal. At the end the script lists every failed step and exits non-zero if there were any, so SLURM records the problem. postprocess.py only runs if at least one docking result exists.

Resuming and re-running

Each step is skipped when its output exists, is non-empty, and is newer than its inputs. After a timeout you can just resubmit, and finished pairs are not redone. Editing an input file re-runs only the steps that depend on it.

The skip checks use file timestamps, so changing a parameter (box size, exhaustiveness, scrub options) does not trigger a re-run. Use FORCE=1 or delete the affected folders.

Output files

receptors/
├── Astra_Zn.pdb                       input structure
└── Astra_Zn/
    ├── Astra_Zn.pdbqt                 prepared receptor
    ├── Astra_Zn_tz.pdbqt              receptor + TZ pseudoatoms
    └── Astra_Zn+ampicillin/           one folder per pair
        ├── Astra_Zn_tz+ampicillin.gpf     grid parameters
        ├── Astra_Zn_tz+ampicillin.glg     AutoGrid log
        ├── Astra_Zn_tz.maps.fld / .xyz    grid description
        ├── Astra_Zn_tz.<type>.map        affinity map per ligand atom type
        ├── Astra_Zn_tz.e.map / .d.map     electrostatics / desolvation
        └── Astra_Zn_tz+ampicillin.pdbqt   docking result (poses)

The map files take most of the disk space. Once a pair’s result PDBQT exists you can delete its maps without affecting the skip logic.

Reading results

The result PDBQT holds the predicted poses, best first. Each pose has a REMARK VINA RESULT line with the binding energy in kcal/mol (more negative is better) and two RMSD values relative to the best pose.

# All poses for one pair
grep "VINA RESULT" receptors/Astra_Zn/Astra_Zn+ampicillin/*_tz+*.pdbqt

# Best score for every pair, sorted
for f in receptors/*/*+*/*_tz+*.pdbqt; do
    echo "$(grep -m1 'VINA RESULT' "$f" | awk '{print $4}')  $f"
done | sort -n
AutoDock4 scores are rough rankings, not accurate binding energies. For a zinc enzyme, check that the pose is chemically sensible: the coordinating atom should sit near the zinc (about 2 Å). A good score far from the zinc is not a zinc-binding result.

The .glg file confirms the box centre and size, and slurm-<jobid>.output holds Vina’s score tables and the list of failed steps. It also shows how many TZ atoms each receptor received.

Viewing in PyMOL

view_docking.py sets up a clear view: pocket residues, the zinc and its coordinating residues, the ligand, dashed lines for zinc coordination and hydrogen bonds, and a printed table of each pose’s score and its shortest zinc-to-N/O/S distance.

PyMOL usually runs on your own computer, so copy the files from the cluster first (quote paths that contain +):

scp user@cluster:/path/to/receptors/Astra_Zn.pdb .
scp "user@cluster:/path/to/receptors/Astra_Zn/Astra_Zn+ampicillin/Astra_Zn_tz+ampicillin.pdbqt" .

Then, in the PyMOL command line (the script can be saved anywhere):

run ~/pymol_scripts/view_docking.py
dock Astra_Zn.pdb, Astra_Zn_tz+ampicillin.pdbqt
dock Astra_Zn.pdb, Astra_Zn_tz+ampicillin.pdbqt, pocket_cutoff=6, show_all=1
snap figure.png

run prints nothing on success, because it only defines the dock and snap commands. Each Vina pose loads as a PyMOL state, so step through them with the arrow keys. Use the original PDB as the receptor, not the _tz.pdbqt.

Limitations

  • Ligands only. Scrub and Meeko are built for drug-like molecules. DNA, RNA and proteins do not belong in ligands/.
  • One zinc per receptor. The box is centred on the first zinc found. Di-zinc enzymes such as metallo-β-lactamases have two, and a bridging hydroxide or water changes how many atoms coordinate each zinc, so check the TZ log line for the site you care about.
  • No reaction modelling. Docking shows pre-catalytic binding geometry. It cannot show bond breaking, and the nucleophile (such as a bridging hydroxide) is not modelled as a ligand.
  • Scores are approximate. Compare ligands against the same receptor, and treat geometry as more informative than small score differences.
